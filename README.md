# CoBudget

Веб-застосунок для обліку особистих і спільних фінансів. Дозволяє вести облік доходів та витрат за категоріями, встановлювати ліміти бюджету та керувати спільним бюджетом разом з іншими користувачами (сім'я, співмешканці, пара) через запрошення за посиланням.

## Проблема, яку вирішує проєкт

Ведення спільного бюджету кількома людьми (сім'єю, співмешканцями) зазвичай ускладнене: немає єдиного місця обліку витрат, запрошення до спільного обліку відбувається вручну через сторонні канали, а перевищення бюджету за категорією виявляється вже постфактум. CoBudget вирішує це, надаючи спільний бюджет з розподілом ролей, миттєвим перерахунком залишку по категоріях та запрошенням учасників за одним посиланням.

## Основні можливості

- реєстрація та автентифікація користувачів (JWT);
- створення особистих і спільних бюджетів;
- запрошення учасників до бюджету за посиланням, без необхідності попередньої реєстрації запрошеного;
- рольова модель доступу в межах бюджету (власник / учасник);
- категорії доходів і витрат із встановленням лімітів;
- облік транзакцій: створення, перегляд, редагування, видалення;
- автоматичний перерахунок залишку бюджету та індикація перевищення ліміту;
- пошук, фільтрація та сортування транзакцій за датою, категорією, сумою та автором;
- адаптивний інтерфейс для desktop і mobile.

## Технологічний стек

| Шар | Технологія |
|---|---|
| Backend | Python, FastAPI |
| ORM / міграції | SQLAlchemy, Alembic |
| База даних | PostgreSQL (production), SQLite (розробка) |
| Автентифікація | JWT (python-jose), bcrypt (passlib) |
| Frontend | HTML, CSS (Tailwind CSS), JavaScript (vanilla) |
| Тестування | pytest |

Обґрунтування вибору технологій наведено в технічному завданні проєкту (`docs/CoBudget_TZ.md`, розділ AC-02).

## Системні вимоги

- Python 3.11 або новіший;
- PostgreSQL 14+ (за потреби локального запуску можна використовувати SQLite без додаткового встановлення);
- Node.js 18+ (лише за потреби локальної збірки Tailwind CSS з вихідних файлів; готова CSS-збірка додається до репозиторію).

## Встановлення

```bash
# 1. Клонування репозиторію
git clone https://github.com/Isoloneya/cobudget.git
cd cobudget

# 2. Створення та активація віртуального середовища
python -m venv .venv
source .venv/bin/activate      # Linux / macOS
.venv\Scripts\activate         # Windows

# 3. Встановлення залежностей backend
cd backend
pip install -r requirements.txt

# 4. Копіювання шаблону змінних середовища
cp .env.example .env
```

## Змінні середовища

Значення задаються у файлі `.env` (не потрапляє до репозиторію, у CI/CD та на хостингу задається окремо):

| Змінна | Опис | Приклад |
|---|---|---|
| `DATABASE_URL` | рядок підключення до бази даних | `postgresql://user:password@localhost:5432/cobudget` |
| `SECRET_KEY` | секретний ключ для підпису JWT | `change-me-to-random-string` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | термін дії токена доступу (у хвилинах) | `60` |
| `INVITE_TOKEN_EXPIRE_DAYS` | термін дії посилання-запрошення (у днях) | `7` |

Для локальної розробки без PostgreSQL достатньо вказати:
```
DATABASE_URL=sqlite:///./cobudget.db
```

## Налаштування бази даних

```bash
alembic upgrade head
```

Команда застосовує всі міграції та створює структуру таблиць відповідно до моделей даних (`User`, `Budget`, `BudgetMember`, `Category`, `Transaction`, `Invite`).

## Запуск застосунку

```bash
uvicorn app.main:app --reload
```

- Клієнтський інтерфейс: `http://localhost:8000`
- Інтерактивна документація API (Swagger UI): `http://localhost:8000/docs`

## Опис API

Повний перелік ендпоінтів доступний у Swagger-документації (`/docs`) після запуску застосунку. Основні групи:

| Група | Базовий шлях | Призначення |
|---|---|---|
| Auth | `/auth` | реєстрація, вхід |
| Budgets | `/budgets` | керування бюджетами |
| Invites | `/invites`, `/budgets/{id}/invites` | запрошення до бюджету |
| Members | `/budgets/{id}/members` | керування учасниками |
| Categories | `/budgets/{id}/categories` | категорії доходів/витрат |
| Transactions | `/budgets/{id}/transactions` | облік транзакцій |

Формат помилок та кодів відповіді детально описаний у технічному завданні (`docs/CoBudget_TZ.md`, розділи AC-06 та AC-13).

## Приклад типового сценарію використання

1. Користувач реєструється через `POST /auth/register`, потім отримує токен через `POST /auth/login`.
2. Користувач створює бюджет: `POST /budgets`, автоматично стає власником.
3. Власник створює категорію з лімітом: `POST /budgets/{id}/categories`.
4. Власник генерує посилання-запрошення: `POST /budgets/{id}/invites`.
5. Інший користувач переходить за посиланням, реєструється/логіниться та приєднується: `POST /invites/{token}/accept`.
6. Учасник додає транзакцію: `POST /budgets/{id}/transactions` — система перераховує залишок категорії та позначає перевищення ліміту, якщо воно відбулося.

## Розгортання

Backend запускається на хостингу командою:

```bash
uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

Статичні файли клієнтської частини видаються тим самим FastAPI-застосунком (`StaticFiles`), тому окремий хостинг для frontend не потрібен. Перед першим запуском на цільовому середовищі необхідно виконати `alembic upgrade head` для застосованої бази даних, адреса якої передається через `DATABASE_URL`.
